# Assets

Status: LIVING LIST — owned by the human (sourcing), maintained by agents (registration)

Every image and sound the frontend uses. The app is built as if they all exist: while a file is missing, the app still works (sounds play placeholder tones, icons fall back to the browser default, link previews have no image).

## How it works

- **Registry**: `apps/web/src/assets/assets.json` lists every asset (id, kind, path under `apps/web/public`). Code refers to assets by id through it.
- **Check**: `npm run assets` lists which files exist and which are missing, and fails if an asset in the registry is not documented here.
- **Adding an asset (agents)**: register it in `assets.json`, use it by id, and document it below with its spec and a generation prompt. Never leave an asset only in code.
- **Delivering an asset (human)**: drop the file at its path, run `npm run assets`, and change its status here to DONE.

Hear and see what exists: `npm run dev` → `http://localhost:5173/design` — the component gallery (Sounds section plays every sound; missing ones play their placeholder tone).

## General direction

Same identity as the UI (`docs/design/DESIGN_SYSTEM.md`): **"Ink & Sticker"** (C-03, chosen 2026-11-15) — warm paper, near-black ink outlines, flat accent fills, hard offset shadows, deliberately drawn and never gradient-and-glass. Palette: paper `#faf6ef`, board `#e9e2d4`, ink `#23201c`, coral `#f4573c`, marigold `#ffc43d`, teal `#2bc4a9`, lilac `#c9b8f0`, sky `#9bd9f2`. The reference for any new art is the direction render `../../../docs/agent/designs/c03/direction-a.html`.

**Sounds**: short, soft, toy-like and musical (marimba, plucks, wooden blocks, glockenspiel, soft synth bells), all in the same key family (C major works) so they sound good together. Normalize to about −16 LUFS, trim silence at the start, no clicks. Format: MP3 (or OGG + MP3), 44.1 kHz, mono is fine for effects.

Notes:

- **The mascot is a slot, not a file yet.** `apps/web/src/ui/Mascot.tsx` draws the placeholder cat of the direction render from code, as P24§3 prefers: the head, eyes, tail and bounce are separate parts driven by the motion tokens. The app is complete without `mascot.primary`; when the creator supplies or approves the final character (`CREATOR_TODO.md` P-15), either the drawing inside the slot is replaced or that Lottie file is mounted in the same wrapper. No screen changes either way, because every screen asks for the slot.
- **The four app icons are placeholders, not final art.** They are generated by `npm run icons` (`scripts/make-placeholder-icons.mjs`), which draws the marigold sticker and the ink play triangle pixel by pixel. T-203 redrew them from the old night-and-owl square so nothing of the retired identity ships; they are still placeholders and P-14 still stands. They exist because a browser refuses to offer installation without the icons the manifest names, and the service worker precaches them (T-202, D-020). Replacing them is a matter of dropping the real files at the same paths — nothing in the code has to change. The maskable one must keep its art inside the central 80 % and stay fully opaque.
- The icons can also be exported from `apps/web/public/favicon.svg` (any SVG → PNG tool).
- Prompt idea for `image.og-share`: *"Flat vector illustration for a party game website banner, 1200×630, hand-drawn sticker style. Warm cream paper background, everything outlined in a 2px near-black ink line with hard offset shadows and no blur or gradients. A cute flat marigold-yellow cat mascot, smiling, surrounded by tilted sticker cards, dice and letter tiles in coral, marigold, teal, lilac and sky blue. Space on the left for the word 'playhoot' in a rounded bold font. No glow, no soft shadows, no text other than the logo."*
- Prompt idea for `mascot.primary`: the same style, one character on transparent background, built in separable layers (head, each ear, each eye, muzzle, body, each paw, tail) so blink, tail-swing and bob can be animated per layer.
